# MiroFish-Offline のエージェント集団シミュレーション設定報告

このプロジェクトは、実在の組織調査の回答者属性を匿名化して作った100体で、Reddit 型の SNS 社会を1週間分シミュレートした。結論を先に書く。当初、シミュレーションの最初の9時間は真夜中に当たり、エージェントは一人も動かなかった。LLM は2世代へ切り替えたが、残りはタイムアウトで会話が止まった。開始時刻・活動時間・同時実行数の3点修正で、はじめて24ラウンド完走にこぎつけた。

## 1. 何をしたか

調査回答者の属性（年齢帯・性別・役職・勤続年数と57の変数スコア）を
100体に埋め込み、マスキングして、 Reddit 環境で会話させた。
変数は特定の企業事情に紐づくものを
除いた一般項目だけを許可し、実在の個人や企業が推定できない形にして
いる。生成物はすべて 旧社名・M&A語彙・業界語 のリストで
スキャンし、ヒット0件を確認してから提出した。

| 項目 | 設定 |
|---|---|
| エージェント数 | 100体（部長5、課長23、一般社員72）— 実調査比率を保全 |
| 環境 | Reddit（OASIS）1ラウンド=60分、24ラウンド=168時間相当 |
| LLM（初期） | gemma4:e4b（Ollama: localhost:11434） |
| LLM（最終） | beamster/Qwen3.8-Flash-Next-Sushi-4bpw（sushi: localhost:12345） |
| 検証 | `scripts/verify_outputs.py` 15/15 PASS、語彙スキャン0件 |

## 2. 初期設定には2つの欠陥が入っていた

### 開始時刻を指定せず、最初の9時間は真夜中だった

シミュレーションの1ラウンド目は 00:00 に始まる。エージェントの
活動可能時間は 08:00〜22:00 に設定してあるので、ラウンド0〜8（00:00〜08:00）は候補者が一人もいない時間帯に当たり、
行動が0件だった。ラウンド9で急に25件、ラウンド10で20件が起きたのは
朝8時に活動時間帯へ入ったからで、エージェントが「目覚めた」わけでは
ない。深夜に投稿しても誰も反応しないのは、SNS の現実と同じである。
開始時刻という発想が無かった。

### 一晩に動くのは8〜12人と上限が低すぎた

1ラウンドに選ぶエージェント数を 8〜12 と決めていたが、100体・168時間
の環境では、全エージェントが一度も選ばれないまま終わる確率が
無視できない。`activity_level` は 0.3〜0.8 の一様乱数で決めており、
低い値の体は選抜の抽選で落ちやすい。結果として 100体のうち20体が
一度も発言しなかった（run2）。これは「発言しなかった人」ではなく
「抽選で回ってこなかった人」である。

### LLM のタイムアウトが短すぎた

初期設定のタイムアウトは180秒だったが、500k コンテキストのモデルが
1件あたりの応答に180秒を超えることがあり、タイムアウトが連発した。
特に gemma4:e4b では180件（旧 run で180件、新 run で86件）が
タイムアウトし、会話の生成が途中で止まった。

## 3. 修正で変えた3つの数字

修正後、24ラウンドすべてが完走し、100体全員が発言し、タイムアウトは
0件になった。修正点はこの3つに尽きる。

| 設定 | 修正前 | 修正後 |
|---|---|---|
| ラウンドの初期時刻 | 00:00（開始時刻を指定せず） | 08:00（`time_config.start_hour=8`） |
| 1ラウンドの同時実行者数 | 8〜12 | 10〜20 |
| エージェントの活動時間 | 08:00〜22:00 | 07:00〜23:00 |
| LLM タイムアウト | 180秒 | 600秒（`MODEL_TIMEOUT` 環境変数） |
| `activity_level`（抽選確率） | 0.3〜0.8 | 0.6〜0.95 |
| LLM | gemma4:e4b | sushi Qwen3.8-Flash-Next-Sushi-4bpw |
| 初期投稿 | 3件・同一テーマに寄りやすい | 8件・雑談系に分散 |
| LLM 接続（実行環境変数） | Ollama localhost:11434 | sushi localhost:12345、`MODEL_TIMEOUT=600` |

修正の再現性は高い。`start_hour=8` にして1ラウンド目から活動時間に
入り、`agents_per_hour_max=20` で抽選に漏れる人が減った。`MODEL_TIMEOUT=600` は
タイムアウトによる停止を防いだ。ただし24ラウンド完走した run5 では
22ラウンドで sushi サーバー側が応答停止し、kill で終わらせている。

## 4. ペルソナは「調査項目の点数」から性格を作った

ペルソナ生成では、変数1件ごとの平均点を高い方から3件、
低い方から2件を取り出し、「関心の向け先」および「苦手な部分」
という2つの傾向として LLM に渡した。例えば満足度:機械・システム・ツール
が強い体は「業務をどう仕組み化するか」に言及し、上司の成果承認が
強い体は「皆さんで」「一緒に」という協調表現が出た。

この設計には2つの欠点がある。第1に、項目名がそのまま
ペルソナの語彙に出るため、調査という事実がにじむ。第2に、
特定の旧社系11項目と部門の焦点系2項目を除外したとしても、残った57項目
にも企業活動が前提の語（部門・影響力度・コミュニケーション頻度）が
残り、生成文が「業務改善会議」化しやすい。実際に run2 では
「週末の予定」という雑談スレッドに「ボトルネック」「ワークフロー」
「KPI」という語が集まり、会話14件中13件が1スレッドに集中した。
run5 では雑談テーマを8件に増やしたことで、会話43件中29件が
通勤時間の使い方（13件）とキッチン道具（8件）に分散し、
スレッドが1つに潰れる現象は抑えられた。

## 5. 会話の中身は「改善文化」へ収束した

24ラウンド完走した run5 の会話は、次のような偏りを見せた。

- 8件中8件に「段取り」「仕組み」「切り替え」「フロー」という語が出る
- 「休みの日にまで業務の話をしたくない」という反論が出た
- メタ調整役も現れた。「このスレッドの目的は情報交換で合っていますか？」
- 反論と調停の後、「完全なOFF と観察は二項対立ではない」という統合発言に到達した

これは初期設定で禁止した語彙ではなく、ペルソナに埋め込んだ
「プロセス改善」「部門間コミュニケーション」への関心が発話を規定して
いる。実調査比率を保全した以上、会話が業務改善トピックに偏るのは
避けられない。

## 6. 次の一手として検討すべきこと

1. **テーマ選択の工夫**: 調査由来のペルソナは業務語彙に寄る。
   雑談・生活・趣味テーマの初期投稿を増やす（既に 3件から8件に増やした）か、
   「業務語彙」を使わない別ペルソナとの混合を検討する。
2. **再現実験**: seed を変えて数本走らせ、スレッド集中と会話が
   再現するか確かめる。1本だけでは傾向が偶然かどうか判断できない。
3. **比較実験の設計**: gemma4 と sushi で結果がどう変わるか
   言えるのは、同一ペルソナで両方を走らせてからである。
4. **sushi の安定性**: 長時間ランで sushi が応答停止する事象に
   見舞われている。サーバリソース・負荷条件を確認する。
5. **ラウンドの追加**: 24ラウンドでは長期の分極化・世論形成は
   観測できない。72〜168時間へ延長したランを回す。

## 7. 階層付き繰り返し囚人のジレンマを追加実施した

雑談だけでは意思決定が観察できないため、部長・課長・一般社員の階層を
踏まえた繰り返し囚人のジレンマを別途走らせ、その結果を初期投稿として
SNS に注入した。結論は明快で、長い関係の下では階層を問わずほぼ全面
協力になり、崩れたのは1ペアだけだった。

### ゲームの設定

- ペア 14組: 部長→課長 5組、部長→一般社員 5組、課長→一般社員 4組
  （シード付きの再現可能な割り当て）
- 1ペアあたり16ターンの反復。利得は裏切りで5点、双方協力3点、
  双方裏切り1点、協力して裏切られると0点。継続確率0.9で
  「関係が続く」見通しを持たせた
- 意思決定は LLM が担当し、自分のペルソナ、相手の階層と名前、
  全履歴を条件に毎ターン C か D を選んだ
- 実装: `backend/scripts/experiment/make_game_sim.py`、結果: `game_results.json`

### 協力率は階層を問わず高かった

| 階層ペア | 双方協力 | 協力率 |
|---|---|---|
| 部長→課長 | 74/80 | 92% |
| 部長→一般社員 | 80/80 | 100% |
| 課長→一般社員 | 64/64 | 100% |

14組中13組が全ターン協力した。崩壊は部長から一般社員への1組のみで、
11ターン目まで協力が続いた後に裏切りが往復し、終盤は相互裏切りで
終わった（履歴: CC CC CC CC CC CC CC CC CC CC DC CD DC DD DD DD）。継続確率が高ければ裏切りの報復が将来に
響くとエージェントが判断した結果で、ゲーム理論の予測と整合する。

### ゲームの結果は SNS 会話に反映された

16ターンの報告を初期投稿にすると、エージェントは数字をそのまま
業務の比喩に読み替えた。「部長→課長の協力率92%が板挟みのせい」
という解釈に、下位がクッション役を担って疲弊するという共感が集まり、
「間接経路の2〜8%のロスを余剰として削ったら現場が止まった」という
実地经验的な反論まで広がった。ゲームが階層の力学を会話に持ち込み、
単なる雑談のときとは違う議論が起きた。

- 会話281アクション・95体稼働（部長5/5、課長21/23、一般社員69/72）
- ゲーム語（協力・裏切り・板挟み・16ターン等）を含む投稿が43件
- タイムライン: `timeline.html`（241イベント）で対話の追跡が可能
