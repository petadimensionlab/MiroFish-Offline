オーツリーとミロフィッシュ・オフラインを組み合わせた実験の仕組みについて、技術的な仕様をご説明します。

この仕組みでは、ミロフィッシュの人工知能エージェントが、オーツリーの反復囚人のジレンマを遊びます。ゲームの回と回のあいだに、エージェントたちは模擬的なSNSで議論し、言葉と行動が互いに影響し合うようになっています。

全体は、四つの部分でできています。

一つ目は、オーツリーのゲームです。ペアの組み方、点数の計算、記録を担当します。ここの記録が、実験の正式な記録になります。オーツリーの側は、ライセンスを分けるため、別の保管場所で管理しています。

二つ目は、橋渡し役のサーバーです。ミロフィッシュのウェブサーバーの中にあり、オーツリーからの問い合わせに対して、エージェントの判断を返します。判断の先取り、議論の進行、記録の突き合わせ、ログの保存も、ここで行います。

三つ目は、ステップサーバーと呼んでいる、シミュレーションを動かすプログラムです。模擬SNSの環境を立ち上げたあと、指示を受けて、議論を一回ずつ進めます。

四つ目は、人工知能のモデルを動かすオラマです。今はジェマ・フォーの小型版を、同時に八つまで処理できる設定で使っています。

ゲームの内容です。二人一組で、相手は固定です。十回くり返します。両者が協力すれば三十点ずつ、相手を裏切れば五十点で相手は〇点、両者が裏切れば十点ずつです。内部の記録では、協力をA、裏切りをBとしていますが、エージェントに見せる選択肢の名前は、橋渡しサーバーの設定で変えられます。

一回の流れをご説明します。

まず、オーツリーが実験を作るときに、ペアの組み合わせと設定を橋渡しサーバーに送ります。橋渡しサーバーは、すぐに一回目の全員の判断を計算し始めます。設定によっては、その前に、点数の表の読み取りを確かめる質問や、信頼についての調査、話題の投稿と最初の議論を行います。

次に、オーツリーの自動プレイヤーが、一体ずつ判断を問い合わせます。橋渡しサーバーは、先に計算しておいた答えを返します。まだ計算中なら、終わるまで待ちます。

全員の判断がそろうと、オーツリーは、実際に記録した結果を橋渡しサーバーに送ります。橋渡しサーバーは裏で、結果を各エージェントの投稿として書き戻し、議論を決められた回数だけ進め、次の回の全員の判断を先取りします。このとき、次の回の判断は、応答を返す前に「計算中」の印をつけておくので、議論が終わる前に判断が出てしまうことはありません。

最後の回のあとには、設定によって、もう一度信頼についての調査を行います。

先取りの仕組みが必要なのは、オーツリーの自動プレイヤーが、完全に一体ずつ順番に動くからです。一体ごとに人工知能を呼ぶと、時間が人数のぶんだけかかってしまいます。

橋渡しサーバーには、四つの窓口があります。実験の設定を受け取る窓口、判断を返す窓口、一回の終わりを受け取る窓口、そして状況を確かめる窓口です。

判断を返す窓口は、同じ実験、同じ回、同じエージェントへの問い合わせには、いつも同じ答えを返します。問い合わせが重なっても、二重に計算しません。一回の終わりを受け取る窓口も、同じ回を二度受け付けることはありません。また、設定されていない実験への問い合わせは、はっきり断ります。これは、サーバーが再起動して設定を忘れたあとに、何事もなかったように答え続けてしまうのを防ぐためです。

設定できる主な項目をご紹介します。

判断の方式は、ランダム、いつも協力、いつも裏切り、しっぺ返し、そして人工知能、から選べます。

選択肢の名前は、AとBの文字か、三角や四角などの意味のない記号かを選べます。どの名前が協力にあたるかと、並べる順番は、ランダムに決まります。ランダムに決める単位は、実験ごとか、エージェント一体ごとかを選べます。今の既定は、記号を使い、実験ごとにランダムに決める設定です。

議論については、回と回のあいだに議論を何回はさむか、ゼロにすれば議論なしになります。議論に参加できるのをゲームの参加者だけにするか、時刻による参加の制限を無視するか、一回の議論に最低何体を参加させるか、も決められます。

結果の書き戻しは、各エージェントがそれぞれ自分の結果を投稿する形、まとめを一件だけ投稿する形、書き戻さない形、から選べます。最初の回の前に話題の投稿を入れること、それを毎回の議論の前にくり返すこともできます。

測定としては、点数の表の読み取りを確かめる質問と、ゲームの前後の信頼についての調査を、それぞれ入れるかどうか選べます。

ステップサーバーへの指示は、ファイルを置く形でやり取りします。指示の種類は、議論を進める、投稿を書き込む、判断のための聞き取りをまとめて行う、状態を返す、などです。判断の聞き取りでは、問いかけの文章の中の決まった場所を、そのエージェントがいま見ている投稿に置き換えます。そして、答えと一緒に、実際に見せた投稿も記録に残します。

ステップサーバーは、同じシミュレーションに対して二つ同時に動かないよう、起動するときに確かめます。

判断を聞く文章では、点数を選択肢ごとに言い直します。たとえば、「三角を選んだ場合、相手が三角なら何点、四角なら何点」という形です。これまでの結果と、いま見ている投稿も入れて、答えは決まった形式で返すよう頼みます。答えが読み取れないときは、もっと厳密な言い方で一度だけ聞き直し、それでも駄目なら、既定の答えを使って「欠測」の印をつけます。

記録として残るのは、次のものです。オーツリーからは、一体の一回ごとに一行の表が出力されます。選んだもの、相手が選んだもの、点数、判断がどこから来たか、欠測かどうか、理由、などが入っています。橋渡しサーバーは、設定、判断、一回の終わり、議論、調査の記録を残します。人工知能の答えについては、問いかけの文章、見せた投稿、答えそのものを、すべて残します。議論の中での行動は、シミュレーションの記録に残り、書き戻した投稿には、書き戻したものだという印がつきます。

一つの実験を集計するための分析用のプログラムもあります。回ごとの協力の割合、相手の前回の行動に応じた協力の割合、人工知能の答えの読み取り状況、議論の中での行動と話題への反応などをまとめます。

運用のうえで守っていただきたいことが、四つあります。

一つ目。シミュレーションの記録を消す前に、古いプログラムを止めて、本当に止まったことを確かめてください。止めたはずのプログラムが裏で動き続け、次の実験の指示を横取りすることがあります。

二つ目。橋渡しサーバーは、自動再起動をしない設定で起動してください。自動再起動が起きると、覚えていた設定が消えてしまいます。

三つ目。実験の途中で、プログラムや問いかけの文章を編集しないでください。

四つ目。ステップサーバーは起動時にシミュレーションの記録を作り直すので、実験は、シミュレーションの写しで行ってください。

以上で、技術仕様の説明を終わります。
