1. 概要

第2報の条件（PD のトポロジ5条件とチャネル4条件）を seed 1・2 で繰り返し、各条件 3ランにした。公共財ゲーム（pgg）にネットワーク会話の4条件を加えた。さらに、会話した相手の実際の選択を後で知らせる「開示」と、悪い評判の相手と話しにくくする「評判」を二者関係（ダイアド）に組み込み、PD で各 3ラン、pgg で各 1ランを実行した。追加は計 30ラン（16体×10期、gemma4:26b 思考あり）で、決定の欠測は 0。

主な発見

  1. 同じ条件でも、ランごとのばらつきが大きい。 会話なしの対照どうしでも、全期平均の協力率は 0.38 / 0.53 / 0.61（seed 0 / 1 / 2）と 0.24 の幅がある。第1期の協力率と第6〜10期の協力率の順位相関は ρ=0.84（33ラン、p=6.7e-10）で、第1期の偶然の差がそのまま後まで残る。
  2. 一般的な職場ペルソナでは、トポロジの差は再現しなかった。 第2報で目立った ER の高さ（全期平均 0.68）は seed 1 で 0.70 と再現したが、seed 2 では 0.59 で対照（0.61）を下回った。BA・WS・ring は対照との差の符号が seed で入れ替わる。
  3. チャネル付きペルソナでは、ネットワーク会話がある条件の協力率が、3 seed すべてで会話なしの対照を上回った。 対照との差は、相性なしが +0.33 / +0.39 / +0.10、相性あり＋記憶が +0.34 / +0.23 / +0.06。会話なしの対照は 3 seed とも最も低い（0.32 / 0.37 / 0.21）。
  4. 選択を開示すると、第1期からの低下が大きくなった。 第2〜10期の平均と第1期の差は、開示ありで -0.32 / -0.29 / -0.24、比較対照（相性あり＋記憶）で -0.10 / -0.10 / -0.19。3 seed とも開示ありのほうが大きく下がった。全期平均は 0.45 ± 0.07（対照 0.51 ± 0.21）。
  5. 評判による接触の重みづけは、効果が小さすぎて判定できない。 開示＋評判の全期平均は 0.44 / 0.65 / 0.99、低下は -0.06 / -0.25 / -0.01 で、2 seed では開示だけ（-0.32 / -0.29 / -0.24）より小さかった。しかし評判の重みが変えたのは、「悪い知らせのある相手」へ会話を始める期待割合の 0.093 → 0.074 だけである。しかも、第1期まで同じ条件の2つの条件で、第1期の協力率がすでに 0.69 対 0.50, 0.69 対 0.88, 0.75 対 1.00（開示 対 開示＋評判）と違っていた。評判の効果とは言えない。
  6. エージェントは宣言を守り、他人のうわさはしない。 「今期これを選ぶ」と言った宣言 833 件のうち 830 件が守られた（開示あり・評判ありの合計）。第三者の名前を出したメッセージは、全 1750 通のうち 0 通。情報は開示の仕組みを通してしか広がらなかった。
  7. 公共財ゲームでは、拠出の開示が拠出を保った（1ラン）。 全期平均の拠出（満額 20）は、会話なし 6.4（第10期 0.0）、相性あり＋記憶 5.8、開示あり 12.9（第10期 10.0）、開示＋評判 7.4。会話なしは理論どおり 0 に収束した。

2. 狙いと目的

研究の問いは第2報と同じで、ゲームの相手以外との言説が、相手との行動を変えるかである。相手と直接話す条件は、合意で行動が決まってしまうので使わない（chat_turns=0、NOTES #51）。PD では、会話の中で「裏切る」と言い出すことはほぼない（宣言はほぼ守られ、裏切りは宣言なしに起きる）。そのため裏切りは、会話の言葉ではなくゲームの記録（相手が協力し自分が裏切った＝exploit）から取り出す。

今回の目的は3つ。

  1. 再現性: 第2報の条件差（1条件1ラン）が、seed を変えても残るかを確かめる。
  2. ゲームの一般性: 公共財ゲームでも、ネットワーク会話が拠出の減衰を変えるかを見る。
  3. 裏切りと評判: 会話した相手の実際の選択を知らせると、協力と会話相手の選び方が変わるか。さらに、悪い評判の相手と話しにくくすると協力が保たれるか。

3. アプローチ（解析方法）

3.1 システムの変更点（NOTES #57）

  • 裏切りイベント（app/services/betrayal.py、純関数・LLM なし）: (1) 言葉: 会話の発言から「今期これを選ぶ」という宣言を規則で取り出し、同じ期の実際の選択と比べる（kept / broken）。(2) 行為: PD で相手が協力・自分が裏切り（exploit）。pgg は宣言額との比較。
  • 開示（net_reveal_choices）: pair では、その期に会話した相手ごとに「相手が選んだもの、相手のペアの相手が選んだもの」を、次の期の記憶に「What you were told after earlier rounds」として入れる（pgg は相手と相手の組の拠出額）。会話の冒頭で「この期の後、互いの選択が知らされる」と伝える。食い違い（言葉を破った、exploit した）は記憶の重み（salience=2）を上げる。
  • 評判（net_reputation_word_weight ρw、net_reputation_choice_weight ρc）: 接触の重みに exp(ρw(2W−1)+ρc(2B−1)) を掛ける。W は言葉を守った割合、B は開示された選択が協力だった割合（Beta 事後平均）。今回は ρw=ρc=2。
  • 解析（scripts/experiment/analyze_betrayal.py）: ログから全イベントを再計算し、オンラインで記録したイベントと一致することを確かめる（開示ありの全 8ランで一致）。開示のないランでも同じ「知らされたはずの事実」を計算できるので、対照はプラセボとして使える。
  • seed: MF_BRIDGE_SEED（oTree の bridge_seed）でネットワーク・接触率・接触の抽選を決め、MF_AGENT_IDS で席順を固定した。LLM のサンプリングには seed を与えていない。

5. 考察

5.1 1ランでは条件の比較はできない

LLM のサンプリングに seed を与えていないので、同じ設定でも第1期の協力率が 0.19〜0.25 ずれる（第1期まで同じ条件の、開示と評判の比較）。そのずれが10期まで残る（ρ=0.84）。第2報の条件差の多く（ER の優位、相性ありの高さ）は、この幅に収まった。今後の比較は、第1期を共変量にするか、第2期以降の変化（低下）で行う。そのうえで、条件あたり 5 seed 以上をとるのがよい。

5.2 会話の効果はペルソナの集合で違う

チャネル付きペルソナでは、会話なしの対照が 3 seed とも低く、会話があると一貫して高くなった。一般的な職場ペルソナでは、会話の有無やトポロジによる差が seed のばらつきに埋もれた。ペルソナの文面（チャネルへの関心の段落）がベースラインを下げ、会話が入る余地を広げたのかもしれない。ペルソナの集合は処置の一部として扱う（第2報 §5.2 と同じ）。

5.3 開示は「現実」を見せ、協力を下げる

PD で相手の実際の選択を知らせると、協力は早く下がった。会話の中での宣言はほぼ守られるため、会話だけでは裏切りが見えにくい。そのため協力的な雰囲気が保たれる。開示で裏切りが可視化されると、協力者も裏切りに転じた（悪い知らせの後の協力 0.50）。人間の実験で知られる「他人の裏切りを知ると協力が崩れる」と同じ向きである。pgg で拠出の開示が拠出を保ったのは、人間の公共財実験で知られる「他者の拠出の観察が条件付き協力を支える」と同じ向きである。いずれも記述的な観察にとどまる。

5.4 評判の仕組みは弱すぎた

評判で接触を変える仕組みは動いた（オンラインとオフラインの再計算が一致し、期待割合が 0.093 → 0.074 に下がった）。ただし効果量が小さく、協力への影響は第1期のばらつきに埋もれた。次の段階では、ρ を大きくする（例: 4〜6）。あるいは、評判をエージェントに見せる（「この人は以前裏切った」と記憶に入れる）経路を加える。エージェントは自分ではうわさを広めない（第三者への言及 0 通）。したがって「評判が広がる」効果を見るには、仕組みとして伝える必要がある。

5.5 妥当性への脅威

  • seed は3つ（pgg は1つ）で、検出力が低い。
  • 開示と評判の比較対照（相性あり＋記憶）は、別の日の別のランである（同じ seed・同じ席順・同じネットワーク）。
  • 開示は会話の冒頭でも予告される（「この期の後、互いの選択が知らされる」）。第1期の差の一部は予告の効果かもしれない。開示の2条件の第1期どうしの差（ランダム）と比べて区別するには、ランが足りない。
  • うわさの検出は、名前の一致による規則ベースで、言い換えは拾わない。

5.6 次にやること

  1. 条件を絞り（会話なし、相性なし、相性あり＋記憶、＋開示）、各 5〜8 seed で反復する。
  2. 第1期を共変量にした比較（または第2期以降の低下）を、事前に主要指標として決めておく。
  3. 評判を強める（ρ を大きくする、評判を記憶に入れる）条件を作る。
  4. pgg の開示を複数 seed で確かめる。
